# Local Agent 実機受け入れテスト · kon-cryo-02

## 目的・権限

対象: `labadmin@kon-cryo-02`、GNOME Shell 46.0 / X11。対象PCのログイン中GUIから操作する。**この成果物はまだGUI/X11実機検証を通過していない。**

まずソースをレビューして依存・セキュリティ面の問題がないか確認し、操作の許可がある場合のみ `bash install.sh` を実行。ユーザーの既存ショートカットやクリップボード履歴は無断削除しない。`sudo`によるaptインストールはユーザーの許可がある場合のみ。最初に既存のClibor互換ツール・Clipboard History・CopyQとの競合を確認する。

## チェック手順（順に実行）

1. **事前条件**: `echo "$XDG_SESSION_TYPE"; echo "$XDG_CURRENT_DESKTOP"; gnome-shell --version` を確認。`bash scripts/diagnose.sh` で XRecord と XTest が利用できるか調査。
2. **静的テスト**: `PYTHONPATH=. /usr/bin/python3 -m unittest discover -s tests -v` を実行。13件以上PASS。`python3 -m compileall -q clibor_lite` も成功。
3. **インストール**: `bash install.sh` 実行後、`pgrep -af clibor_lite.app`、`cat ~/.local/state/clibor-lite/app.log` を確認。実体が1プロセスのみであること。
4. **ホットキー**: テキストエディタを開いたまま左Ctrlを2回（間隔350ms以内）押す。ポップアップ表示。右Ctrlでも試す。Escで消える。単独Ctrl、Ctrl+C、Ctrl+V、Ctrl+A、長押し、左右Ctrlの交互押しではポップアップが出ないこと。
5. **履歴**: エディタで `ALPHA`, `日本語サンプル`, `BETA` を順にコピー。Ctrl×2で新しい順に表示。日本語検索、矢印、Enter、数字1、クリックで選択。重複コピーが最新へ移動。画像コピーはクラッシュせず無視。
6. **自動貼り付け**: テキストエディタのカーソル位置を記憶し、Ctrl×2 → 履歴選択。ポップアップが閉じて元のカーソル位置に貼られること。**文字化け・二重貼付・意図しない別ウィンドウへの貼付がないことを最重要で確認**。Firefox/Chrome、VS Code/端末などでも可能な範囲で検証。失敗時は設定の待機時間を160→300msに変更して再試験。
7. **日時**: 定型文タブ → `YYMMDD` および `YYMMDD-HHMM` を選ぶ。実機の現在日時と一致。月末・日付切替はモックまたはユニットテストで確認。設定で `{date:%Y-%m-%d}` を新規追加し、正しく展開されること。
8. **任意の直接キー**: 既存カスタムショートカットをバックアップまたはスクリーンショット。`/usr/bin/python3 scripts/gnome-shortcuts.py install` を実行し `Ctrl+Alt+1`,`Ctrl+Alt+2` をテスト。GNOME既定操作との衝突確認。`remove` でClibor Lite用2件のみ消え、既存設定が残ることを検証（必要な場合のみ再登録）。
9. **設定**: `~/.local/bin/clibor-lite settings` でGUIを表示。監視OFFで新規コピーが履歴へ追加されないこと。自動貼付OFFでクリップボードコピーのみになること。数値の保存と再起動後の反映を確認。
10. **永続性**: ログアウト→再ログインで自動起動し、履歴・定型文が保持されること。明示的な履歴削除後に内容が復活しないこと。DB/設定ファイル権限0600、ディレクトリ0700を確認。
11. **負荷**: `ps -C python3 -o pid,rss,pcpu,command` 等でアイドル時RSS・CPU%を測定（3〜5分）。通常入力を妨げるCPU使用率や体感遅延がないこと。
12. **例外系**: ロック画面から復帰、2画面接続、長文（20万文字以上）、複数改行、クリップボードが空、ウィンドウ非アクティブ、同時起動、X11切断後の動作を確認。例外発生時は最小再現手順を収集。

## 受け入れ判定

- **P0**: 起動できない、Ctrl×2が検知できない、Ctrl+C/Vが妨げられる、意図しない窓へ貼付ける、ファイルが破損する、権限や個人情報上の問題。1件でもあれば導入失敗。
- **P1**: ポップアップ操作、検索、テンプレート日時、UIフォーカス、GNOMEショートカットが期待どおりでない。修正して再試験。
- **P2**: 見た目、余白、ウィンドウの表示位置、応答時間など改善可能な項目。

## 失敗時のログ・報告形式

1. 実行環境（OS/デスクトップ/セッション/モニター数）。
2. コマンドと依存バージョン（`bash scripts/diagnose.sh`）。
3. テスト番号と PASS/FAIL、実際の操作、期待との差。
4. 例外・ログ（**履歴・パスワード・ユーザー個人データはマスク**）。
5. 修正内容・差分・再テスト結果・CPUとRSSの値。
6. `P0/P1/P2` 分類と「導入継続可 / 修正後再試験 / アンインストール推奨」を明記。

**修正時の原則**: CliborらしいCtrlダブルタップとポップアップ中心の操作感を守り、巨大な依存や非必須機能を追加しない。UI改善時はデジタル庁デザインシステムを参考に、設定のラベル・文字サイズ・フォーカス・余白を優先する。問題の切り分けなしに大規模改修しない。
