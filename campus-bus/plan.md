# 大阪大学 学内連絡バス検索 Web App 実装計画

## 0. このPRの位置づけ

このPRは、豊中・吹田・箕面のキャンパス間を走る大阪大学学内連絡バスについて、スマートフォンから「次に乗れる便」「指定時刻に出発／到着できる便」「往復で利用できる便」を検索できるWebアプリを実装するためのDraft PRとする。

現段階ではUIモック受領前のため、先に仕様・データ構造・検索ロジック・検証条件を確定する。UIは後から提示されるモックを正本として、このブランチへ実装する。

## 1. 目的

公式時刻表をそのまま眺めるのではなく、Yahoo!乗換案内やGoogleの経路検索に近い操作感で、利用者の現在地・日時・希望条件から適切な便を提示する。

主な利用場面は以下とする。

- アプリを開いた時点で、現在いるキャンパスから次に乗れる便を確認する
- 豊中・吹田・箕面から出発地と到着地を指定して検索する
- 「今すぐ」「出発時刻指定」「到着時刻指定」を切り替える
- 豊中―吹田間で箕面を経由しない直行便だけに絞る
- 往路と復路をまとめて検索し、「行った後、いつ帰れるか」を確認する
- 運休日や最終便後には、次の運行日を含めて案内する

## 2. 公式データと前提

### 2.1 正本

- 大阪大学「学内連絡バス」
  - https://www.osaka-u.ac.jp/ja/access/bus
- 2026年度運休日
  - https://www.osaka-u.ac.jp/ja/access/files/2026bus/HP_r8bus_unkyuu.pdf/@@download/file

アプリ内の時刻表は2026年4月1日改正の公式情報を正本とする。データ更新日、対象年度、公式ページへの導線を画面内に表示する。

### 2.2 利用条件

公式案内上、学内連絡バスはキャンパス間移動を伴う授業・教育・研究等のための学生・教職員向け無料バスであり、通常の通学・通勤用途を目的としない。アプリは利用可否を判定するものではなく、注意書きを簡潔に表示する。

### 2.3 運行日

原則として授業期間中の平日のみ運行する。土日祝日に加えて、年度ごとの春季・夏季・冬季休業、大学行事等による運休日を `service calendar` として管理する。

2026年度の主な運休期間・運休日は以下。

- 2026-04-01〜2026-04-09
- 2026-04-30〜2026-05-01
- 2026-08-12〜2026-09-30
- 2026-11-02
- 2026-11-04
- 2026-12-28〜2027-01-03
- 2027-01-15
- 2027-02-04
- 2027-02-09〜2027-03-31

特別ダイヤは通常ダイヤへ混ぜず、別サービスとして登録できる構造にする。

### 2.4 停留所とキャンパス概念

UI上は利用者に分かりやすい3キャンパスを基本単位とする。

- 豊中キャンパス
- 箕面キャンパス
- 吹田キャンパス

一方、検索エンジン内部では実際の停留所を区別する。

- `toyonaka`：豊中地区
- `minoh`：箕面キャンパス前
- `suita_convention`：コンベンション前
- `suita_engineering`：工学部前
- `suita_human_sciences`：人間科学部前

吹田キャンパスを選んだ場合、方向に応じて実際の発着停留所を結果へ明示する。将来的に「吹田のどの停留所から乗るか」を詳細条件として選べるようにする。

### 2.5 便種別

以下を明示的に区別する。

- 豊中―吹田の直行便
- 豊中―箕面―吹田の経由便
- 豊中―箕面の箕面止まり便
- 箕面始発便
- 吹田側の工学部前／人間科学部前を順に通る便

「直行便のみ」は、単に乗換がないことではなく「豊中―吹田間で箕面を経由しない便」を意味する。UIでは `箕面を経由しない直行便` と表記し、誤解を避ける。

## 3. MVPの機能要件

### 3.1 ホーム：次に乗れる便

初期表示で以下を提示する。

- 現在日時
- 推定または選択中の出発キャンパス
- 次に出る便の発車時刻
- 到着キャンパスと到着予定時刻
- 発車までの残り時間
- 直行／箕面経由／箕面止まりの区別
- 次の2〜3便
- 運休日の場合は「本日は運休」と次の運行日

初回は位置情報を強制しない。現在地の決定優先順位は次の通り。

1. ユーザーが明示的に選択したキャンパス
2. 位置情報の利用を許可した場合のキャンパス圏判定
3. 前回選択したキャンパス
4. 未設定状態で選択を促す

### 3.2 片道検索

入力項目：

- 出発キャンパス
- 到着キャンパス
- 日付
- 検索種別
  - 今すぐ
  - 出発時刻
  - 到着時刻
- 時刻
- 直行便のみ（豊中―吹田検索時に表示）

結果カード：

- 発車時刻 → 到着時刻
- 所要時間
- 発着停留所
- 経由地
- 発車までの時間
- 便番号または内部trip ID
- 公式時刻表ベースであり、道路状況による遅延を含まない旨

### 3.3 往復検索

入力項目：

- 往路の出発地・到着地・日時
- 復路条件
  - 復路の出発時刻を指定
  - 到着後の滞在時間を指定（例：60分、90分、授業1コマ後）
  - その日の最終帰着候補を見る
- 往路／復路それぞれの直行便条件

出力：

- 往路候補と、それに接続可能な復路候補を1組として表示
- 現地滞在可能時間
- 復路最終便への余裕
- 復路が存在しない場合の明示

### 3.4 履歴・よく使う経路

ログインやサーバー保存はMVPでは行わず、端末内 `localStorage` を使用する。

保存対象：

- 前回選択した出発キャンパス
- よく使う区間
- 直近の検索条件
- 曜日・時間帯ごとの利用回数

ホームの推奨は、位置情報だけに依存せず、現在の曜日・時間帯と過去の選択傾向から候補を並べる。推奨は確定扱いにせず、常にワンタップで変更可能とする。

## 4. 検索ロジック

### 4.1 基本方針

時刻表を画面表示用の配列として直接持たず、以下の正規化データから検索する。

- stops
- campuses
- trips
- stop_times
- service_calendars
- service_exceptions
- source_metadata

検索は指定日の有効なserviceを確定した後、originとdestinationの両方を通過するtripを抽出し、stop sequence順と時刻条件を評価する。

### 4.2 出発時刻検索

1. 指定日の運行可否を判定
2. 出発地を通る便を抽出
3. 出発時刻が指定時刻以降の便に限定
4. 到着地が出発地より後のstop sequenceにある便だけを残す
5. 直行条件、停留所条件を適用
6. 発車時刻順に最大5件を返す

### 4.3 到着時刻検索

1. 指定日の運行可否を判定
2. 到着時刻が指定時刻以前の便を抽出
3. 出発地が到着地より前のstop sequenceにある便だけを残す
4. 条件適用後、到着時刻が遅い順に候補を返す

### 4.4 往復検索

往路候補ごとに復路検索の基準時刻を計算する。

- 復路時刻指定：指定時刻以降
- 滞在時間指定：往路到着時刻＋滞在時間以降
- 最終便確認：その日の復路候補の最終便

往路到着後に復路へ乗れない組合せは除外する。最終帰着時刻も表示する。

### 4.5 運休日・日跨ぎ

当日に便がない場合、単に「該当便なし」とせず、最大60日先まで次の運行日を検索する。年度データの範囲外になった場合は、翌年度時刻表が未登録であることを表示して公式ページへ誘導する。

## 5. データ形式

想定ファイル：`campus-bus/data/timetable-2026.json`

```json
{
  "schemaVersion": 1,
  "academicYear": 2026,
  "effectiveFrom": "2026-04-01",
  "source": {
    "title": "大阪大学 学内連絡バス 2026年度",
    "url": "https://www.osaka-u.ac.jp/ja/access/bus",
    "verifiedAt": "2026-08-07"
  },
  "stops": [],
  "campuses": [],
  "services": [],
  "serviceExceptions": [],
  "trips": []
}
```

各tripは、便全体の出発・到着だけではなく、停留所ごとの時刻を持つ。

```json
{
  "id": "TY-08",
  "serviceId": "weekday_2026",
  "routeVariant": "toyonaka-minoh-suita",
  "direct": false,
  "stopTimes": [
    { "stopId": "toyonaka", "departure": "09:20", "sequence": 1 },
    { "stopId": "minoh", "arrival": "09:40", "departure": "09:40", "sequence": 2 },
    { "stopId": "suita_convention", "arrival": "09:55", "departure": "09:55", "sequence": 3 },
    { "stopId": "suita_engineering", "arrival": "10:00", "sequence": 4 }
  ]
}
```

時刻表に `－` と記載される停留所は、null時刻ではなくstop sequence自体を持たせない。これにより「その便は停車しない」を明確に扱う。

## 6. 技術構成

既存 `kon-lab` はGitHub Pages上で静的HTMLツールを公開しているため、MVPはバックエンドを持たない静的Webアプリとする。

### 6.1 想定構成

```text
campus-bus/
├── index.html
├── plan.md
├── README.md
├── manifest.webmanifest
├── styles/
│   └── app.css
├── src/
│   ├── app.js
│   ├── data-loader.js
│   ├── search-engine.js
│   ├── service-calendar.js
│   ├── preferences.js
│   ├── geolocation.js
│   └── formatters.js
├── data/
│   ├── timetable-2026.json
│   └── schema.json
├── scripts/
│   └── validate-timetable.mjs
└── tests/
    ├── search-engine.test.mjs
    ├── service-calendar.test.mjs
    └── fixtures/
```

### 6.2 採用方針

- HTML / CSS / JavaScript ES Modules
- GitHub Pagesでそのまま配信可能なzero-build構成
- 検索ロジックとDOM操作を分離
- Node.js標準テストランナーでロジックを検証
- 外部APIやDBへ依存しない
- PWA対応はMVP後半で追加可能

位置情報はブラウザのGeolocation APIを利用するが、緯度経度を保存・送信しない。位置情報を拒否しても全機能を利用できる設計にする。

## 8. 非機能要件

- iPhoneを主対象とし、幅375〜430pxで主要操作を片手で完結できる
- 画面初期表示から次便確認までを極力1秒以内にする
- オフラインでも最後に取得済みの時刻表を閲覧可能にする余地を残す
- WCAGを意識し、色だけで便種別を区別しない
- キーボード操作、aria-label、十分なタップ領域を確保する
- 日付・時刻処理はAsia/Tokyo固定とし、端末タイムゾーン差による誤判定を防ぐ
- 時刻表の変更・運休・遅延をリアルタイム保証しない旨を明示する

## 9. テスト条件

最低限、以下を自動テストする。

1. 豊中→吹田の直行便が箕面経由便と区別される
2. 豊中→箕面止まり便が吹田行として返らない
3. 箕面始発便を箕面→豊中／吹田で検索できる
4. 工学部前発と人間科学部前発の5分差を保持する
5. 出発時刻検索で指定時刻より前の便を返さない
6. 到着時刻検索で指定時刻を超える便を返さない
7. 土日祝日に通常便を返さない
8. 2026-08-12〜2026-09-30を運休と判定する
9. 最終便後は次の運行日を返す
10. 往路到着前に出る復路を組み合わせない
11. 直行便のみ指定時に箕面経由便を除外する
12. `－` の停留所を停車扱いしない
13. 同一キャンパス指定時に検索を実行せず入力エラーを返す
14. 年度範囲外では公式ページへの更新案内を返す

時刻データ自体については、公式Web表の全行との突合チェックを行う。便数、各停留所の発着時刻、停車しない停留所、運休日を検証対象とする。

## 13. 現時点の解釈上の確認事項

依頼中の「往復でもいつ買えるんか」は、「往復検索で、行った後にいつ帰れるか」を求めるものとして設計している。購入・予約機能を意味する場合は別要件となるが、学内連絡バスは無料であるため、現仕様には購入処理を含めない。

リアルタイム位置、遅延、満席情報は公式データ提供元が確認できないためMVP対象外とする。運休・遅延はKOANまたは阪急バス等の公式情報を確認するためのリンクを表示する。
