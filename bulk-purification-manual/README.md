# 大量精製 全体統括・引継ぎマニュアル

この資料は、大量精製の**日程調整・事前準備・当日の全体進行・結果整理・反省会・保存**までを、責任者としてどう回しているかをまとめたものです。

実験操作そのものは各回の最新版Protocolを参照してください。ここでは、Protocolに書いてある操作条件を重ねて説明するのではなく、**誰に何を依頼するか／何をいつ更新するか／どの資料を残すか／どこまで連絡するか**を中心に記載します。

---

# 1. 精製日程を決める

## 1.1 日程調整

調整さん等で候補日を集めます。

通常運用では、**火曜精製 → 木・月・金に培養対応**の並びが最も安定していたため、基本は火曜日を中心に候補を出せば問題ありません。

日程調整を見るときは、精製当日の参加者だけでなく、**その精製日に向けた培養を誰かが担当できるか**も確認します。特に火曜以外のイレギュラー日程では、培養対応者まで確認してから決めます。

候補がある程度絞れたら昆さん・関係者と相談して決定し、全体へメールで通知します。回答が揃わない場合は、対面や個別LINEでも確認します。

### 日程調整メール

日程調整メールは、実際に使っていた文面をベースにしてください。必要以上に短くせず、**回答期限・対象期間・何回実施したいか・候補日の考え方**が分かる形にします。

# 2. 日程が決まったらすぐにやること

## 2.1 遠心機2台の予約

集菌用と濃縮用の遠心機を予約します。

使用時間はずれることがあるため、平田は**0:00頃〜17:00程度を広く確保**していました。濃縮が遅くなる回もあるので、必要なら18:00頃まで押さえて構いません。

実使用時間だけ細かく分けることもできますが、全体進行がずれたときに困らない取り方を優先していました。

## 2.2 TEMの予約

TEMは当日を終日押さえます。

平田名義で予約していた時期もありますが、報告者と実使用者がずれるため、現在は**増田君名義で荒木さんに依頼**する運用です。

荒木さんには口頭だけでなく、メールでも日時・利用者を伝えておく方が確実です。

## 2.3 大量処理室の掲示

大量処理室で大量精製を行う日を、事前に貼り紙で周知します。

大量精製が優先という意味ではなく、長時間使用するためのお願いとして掲示します。

※2026年12月までの既定日程分は平田が掲示済みです。日程変更・追加があれば対応してください。

## 2.4 培養予定をカレンダーへ入れる

精製日が決まった段階で、培養3回もカレンダーへ登録しておく方が安全です。

培養の流れは次の3段階です。

**Stock → 前培養2枚＋新Stock / 前培養 → プレート培養7枚 / プレート培養7枚 → 液体培養**

詳細な培養操作はProtocolを参照してください。

# 3. 培養と培地作製を回す

精製までに、培地作製と培養3回を進めます。

培養は分担して構いません。担当者が決まったら、その人が実施することが分かるようにしておきます。

培地作製は、手が空いていれば**増田君のTEM観察の裏で作り始める**と効率が良いです。

この章では培養条件や無菌操作の注意事項までは扱いません。そこは最新版Protocolに従ってください。

## 4.1 毎回のProtocol更新

リマインドを送る前に、前回Protocolをコピーして今回分へ更新します。

更新する場所は主に次の通りです。

| 場所 | 更新内容 |
|---|---|
| 注意事項 | 直近の反省会で出た内容のうち、次回特に気を付ける点だけを短く記載。古い内容はさらに要約して「過去の精製回の反省」へ移す |
| タイムスケジュール | 人数や担当変更に合わせて更新。`◎：主担当 / ○：サブ担当 / △：フォロー` を基本に、並行作業ごとに色分け |
| Protocol本体 | ダイニン種など、その回で実際に変わる箇所だけ修正。見落としやすい変更点はハイライトを残す |
| UnoQの前回データ | 前回の Fr / UV / Cond / Time を最新回へ差し替え。必要ならクロマト画像も更新 |
| 濃縮の前回記録 | 必要に応じて最新回へ差し替え |

UnoQや濃縮の前回値はResultsやNoteから確認できるため、毎回の差し替えは必須ではありません。ただし、当日Protocolだけ見て作業する人には最新値がある方が使いやすいです。

## 4.2 当日用PDF

実験中に見やすい4-in-1 PDFは、以下のN-in-1 PDFツールで作成しています。

`https://naoshi-git.github.io/kon-lab/`

目次など当日不要なページを削除し、見開きで同じ工程がまとまるように空白ページを足す／削る、元PDFの余白を少し切る、最終A4から少し余白を取る、といった調整をしていました。

必須作業ではありませんが、当日のProtocolを扱いやすくするために行っています。

# 5. 前日〜直前の準備

前日準備の詳細はProtocolにあります。責任者がすべてを自分で実施するのではなく、**担当が決まっている準備は担当者へ依頼し、全体として抜けがない状態にする**ことが重要です。

特に、フラコレ周辺などUnoQ側の準備は前嶋さんが担当してくださっているものがあります。TEM関連を含め、担当者がいる準備は早めに「これお願いします」と一声かけておきます。

平田側で、当日朝を楽にするためによくやっていた準備は次のようなものです。

**Falconを用意 / Dibucaineを作る / MQを汲む / HMDS用ビーカーを先に出す / カゴへ入れられる物品をまとめて入れておく**

いずれも当日対応は可能ですが、朝の準備時間が短くなります。

また、大野さん＝見学、柳瀬君＝フォロー等、その回に参加するメンバーにはProtocolを送り、事前に一声かけておきます。

# 6. 当日の全体進行

## 6.1 朝

Protocolどおりに精製準備を行います。

一人で準備すると1時間程度かかりますが、前嶋さんが手伝ってくださる回は40〜50分程度で進んでいました。

## 6.2 精製中に責任者が見ること

精製中は、自分の実験操作に加えて全体を見ます。

特に意識していたのは、**人手が余らないように作業を分ける / 同時作業しやすいよう備品の位置を整える / 山本さんが一人で多くの作業を抱えないよう分担する / 後から確認できる程度に写真と時刻を残す**、という点です。

大幅に遅れた場合は、メールで関係者へ連絡し、昆さんにも伝えます。濃縮へ入るタイミング等は今井さんと連携します。山本さんから進行や結果を聞かれた場合は、その時点で分かっている範囲を共有します。

# 7. UnoQ結果の取り出し

UnoQの操作そのものはProtocol、データの取り出しは添付の**UNICORN データ抽出マニュアル**を参照してください。

責任者として行っていた流れは次の通りです。

1. fまでFractionが出たら、下さんへ「片付けてOKです」と口頭またはLINEで伝える
2. AKTA用PCを後で使える場所へ置いておいてもらう
3. `Evaluation` からResultを開く
4. 必要なcurveを表示し、スクリーンショットを取得
5. `File > Export > Curves` からExcelへExport
6. 必要な値・画像をResults PPTXへ反映

表示するcurveやmarkerの使い方、peak table、Compare等の細かい操作はUNICORNマニュアルを参照してください。

# 8. Bradford濃度測定データ

共有OneDriveの以下のExcelを使用します。

`04.大量精製\Results\Bradford濃度測定_大量精製.xlsx`

基本操作は、**前回sheetを複製 / 日付を変更 / 黄色ハイライト部へOD値を入力 / Dilutionへ希釈率を入力**です。

検量線・濃度・ラベル付きグラフは自動で更新されるので、結果画面をスクリーンショットしてResults PPTXへ貼ります。

例として260817 sheetでは、a/b・c・d・gについてOD595と希釈率を入力し、最終濃度を算出しています。

# 9. 精製終了後〜反省会まで

Results PPTXは精製中から少しずつ作ります。

UnoQ / 濃縮 / 濃度等、結果が出た項目から入力しておくと後が楽です。朝や待ち時間に今回分の枠だけ整えておき、値が出たら埋める形でも構いません。

精製終了後は、柳瀬君へお礼のLINEを送り、大野さん等にも必要に応じて一声かけます。

その日のうちに、関係者全体へ**結果速報＋反省会日程**をメールします。反省会の日程調整は文頭に置いた方が見落とされにくいです。

通常は金曜開催で固定しているため、予定どおりであればリマインド中心でも構いません。日程が決まったらメール・LINEで連絡し、今井さん・山本さんには必要に応じて個別でも確認します。

速報と最終Resultsは精製に関係したメンバー全員へ送ります。一方、反省会の細かい議論だけの連絡では、柳瀬君・下さん・大野さん等を外すことがあります。

# 10. Results PPTXを作る

前回のResults PPTXを**ファイルごとコピーして、今回分へ書き換える**のが基本です。平田在学中は平田OneDrive上で共同編集し、複数人で並行して更新して構いません。

## 10.1 最初にやること

コピー直後は前回データが残っています。

まず、後で参照することが多い**Chromato / ネガステ / 精製の反省と改善 / 反省会**を、PPTX末尾の過去データ側へコピーします。

その後、今回結果のスライド右肩にある `260817` のような日付を今回の日付へ変えます。置換機能を使って構いませんが、過去結果の日付まで変えないようにします。

## 10.2 各sectionの更新

縦に手順を増やしすぎないため、更新内容は以下だけ把握しておけば十分です。細かいレイアウトは前回PPTXをそのまま踏襲してください。

| Section | 更新内容 |
|---|---|
| 精製の反省と改善 | 今回の結果サマリー / 発生した問題 / 次回へ残したい点 |
| ネガステ結果一覧 | 今回画像へ更新。反省会で最初に見やすいよう一覧化 |
| 反省会 | 精製直後は空欄 / 反省会後に議論内容を整理 |
| 基準結果 | 原則変更なし |
| UnoQ Frの結果 | 前回表を下段へコピー / 上段を今回データへ更新 / a,b,c,d,e,g,fの位置は今回クロマトに合わせる / 下部赤字へ前回比較の所感 |
| Chromatoの比較 | UNICORNのCompare Curveで過去runと重ねた画像を貼る |
| 濃縮 | 今回の濃縮過程を入力 |
| 濃度測定 | Bradford Excelのグラフを貼る |
| ネガステ | 増田君が主に更新。過去Resultsへコピー後、今回欄の画像・赤文字を一度消して入力しやすくする |
| サンプル残数・精製履歴 | 今回結果を追記。過去履歴は消さない |
| 使用バッファー記録 | 今回使用分を追記。前嶋さんが更新してくださることが多い |

UnoQのスクリーンショットは、**a/b前の谷〜fの最大ピークまでが入る程度の幅**にすると比較しやすいです。

画像と赤文字の位置は既存PPTXのプレースホルダーをそのまま使ってください。

反省会の内容までResultsへ反映したら、最終版を共有します。

# 14. 関係者とのコミュニケーション
