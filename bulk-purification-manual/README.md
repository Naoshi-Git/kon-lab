# 大量精製 指揮・運用 引継ぎマニュアル

> **この文書は「実験操作Protocol」ではなく、大量精製を1サイクル成立させるための運用・指揮マニュアルです。**
>
> 実際の試薬量、遠心条件、UnoQ条件、濃縮・ネガステ等の操作は、その回の最新版Protocolを正本としてください。本書は、**日程調整、予約、培養の起動、Protocol更新、当日の全体進行、データ回収、Results作成、反省会、共有・保存までを誰が何の順で回すか**を整理します。

## 0. 最初に：この仕事のゴール

大量精製の責任者の仕事は「自分が一番多く手を動かすこと」ではありません。

ゴールは次の3点です。

1. **精製を成立させる**：培養・装置・部屋・人員・試薬・TEMが途切れず接続される状態を作る。
2. **quality / quantity を守る**：異常があるときに強行せず、判断に必要な記録を残す。
3. **次回が前回より楽になる形で記録する**：Protocol、Results、クロマト、TEM、反省会、NASを一つの履歴として残す。

2026-08時点では、今後の中心担当を**前嶋・増田**へ移す方針です。最終的には、どちらか1名が欠けても、残るメンバーで一連の運用を回せる状態を目標とします。

---

# 1. 全体フロー

大量精製1回は、概ね次の順で進みます。

```text
日程候補を集める
  ↓
培養対応者まで含めて実施日を確定
  ↓
遠心機・TEM・大量処理室を確保
  ↓
D-12 Stock → 前培養 plate + 新Stock
  ↓
D-8  前培養 → 培養 plate
  ↓
D-7前後 Protocol改訂 + 1週間前リマインド
  ↓
D-4  plate → 液体培養
  ↓
D-1  前日準備
  ↓
D0   大量精製 + UnoQ/TEM/濃度/凍結 + 速報
  ↓
反省会
  ↓
Results確定 + PDF共有 + PPTX/NAS保存
  ↓
ラボメンテ・次回へ反映
```

## 1.1 火曜精製を基本とする理由

通常運用では、**火曜日を第一候補**にすると培養サイクルが安定します。

- D-12：木曜
- D-8：月曜
- D-4：金曜
- D0：火曜精製

この `木 → 月 → 金 → 火` のリズムが最も扱いやすいため、通常期間の調整さんはまず**火曜中心**で投げるのが無難です。

> **重要**：曜日名より `D-12 / D-8 / D-4` を正本にしてください。最新版Protocol内には、液体培養の注記で曜日表記が実運用と整合しない箇所が残る可能性があります。イレギュラー日程では必ず精製日から逆算してください。

# 2. 日程を立ち上げる

## 2.1 調整さんを投げる前に決めること

まず以下を決めます。

- 何月に何回実施したいか
- 火曜固定でよいか、夏休み等で曜日を外すか
- 対象期間内で避けるべき会議・ゼミ・出張・停電等がないか
- 主要メンバーだけでなく、**D-12 / D-8 / D-4 の培養対応者**を確保できるか

日程調整では「精製当日が空いている」だけでは不十分です。

**候補日ごとに、精製日から12日前・8日前・4日前の培養が誰かしらで実行可能かを確認してから確定**します。

## 2.2 調整さんの投げ方

通常期間は火曜を候補にし、夏休み等は広めの日程を候補にして構いません。

調整依頼時は以下を明記します。

- 回答期限
- Toに入っている人は回答必須かどうか
- 実施目標回数
- 「△」を増やしすぎると調整不能になること
- 精製当日だけでなく培養対応も後から検証すること

候補が集まったら、

1. 全員または必要人数が揃う日を抽出
2. D-12 / D-8 / D-4 を担当できるか学生側で検証
3. 昆さん・山本さん等と相談
4. 日程確定
5. 全体メールで通知

の順です。

### 日程調整メールのひな型

```text
件名：【要回答：○/○締切】大量精製 日程調整のお願い（○〜○月）

皆様

お疲れ様です。
○〜○月の大量精製について、日程調整をお願いいたします。

【回答期限：○月○日】

以下の調整さんより、対応可能な日程をご入力ください。
（必要に応じて：Toの皆さまは全員ご回答をお願いします）

URL：...

候補確定後、D-12 / D-8 / D-4 の培養対応可否を学生側で確認したうえで最終決定します。

よろしくお願いいたします。
```

## 2.3 確定後は「その場で」次の予約へ進む

日程だけ決めて止めると、高確率で予約や培養登録が漏れます。

**精製日が確定したら、その日のうちに Section 3 の予約とカレンダー登録まで終わらせる**のが安全です。

# 3. 日程確定直後に確保するもの

## 3.1 遠心機 ×2

最新版Protocolで事前予約対象となっている装置は次の2台です。

- 実習室 b237：`himac CR200GIII`（主に繊毛単離）
- 実習室 b237：`TOMY GRX250`（主に濃縮）

運用上は、時間ずれ・前夜冷却・濃縮の遅延に耐えるため、かなり広めに押さえて構いません。

過去運用例：

- 00:00頃〜17:00
- 濃縮が遅れる可能性を考えるなら〜18:00程度

2台を実際の使用時間だけ細かく分割して予約してもよいですが、全体進行の遅延で予約競合が生じないよう、**責任者は「確実性」を優先**してください。

## 3.2 TEM

TEMは、観察担当と使用名義が一致するように運用します。

2026-08時点では、平田名義ではなく**増田名義を基本**とし、荒木さんへ依頼する運用へ移しています。

- 当日は原則終日確保
- 必要に応じて前夜も確保し、光軸合わせ等に備える
- 口頭だけでなく、**メールでも日時・利用者・用途を残す**

「伝えたつもり」を避けるため、曖昧な返答だった場合は日時を復唱して確認します。

## 3.3 大量処理室

大量処理室は大量精製で占有時間が長いため、利用予定日を掲示します。

大量精製が優先権を持つわけではないため、**「お願い」の形で事前掲示する**運用です。

2026-12までは平田側で掲示済みの予定がありますが、日程変更・追加時は再確認してください。

## 3.4 カレンダーへ培養3件を登録

精製日を登録するだけでは不十分です。

同時に以下も登録します。

- D-12：Stock → 前培養 plate ×2 + 新Stock
- D-8：前培養 → 培養 plate ×7
- D-4：培養 plate ×7 → 液体培養

担当が決まっていれば担当者も書きます。

# 4. 培養サイクルを回す

## 4.1 基本3ステップ

14 Lスケールを例にすると、運用上の培養は以下の3段階です。

### D-12：Stock → 前培養 plate + 新Stock

- 前培養 plate：2枚
- 新Stockも同時に植え継ぐ

### D-8：前培養 → 培養 plate

- 14 Lなら培養 plate：7枚

### D-4：培養 plate → 液体培養

- 2 Lフラスコへ移行

詳細な無菌操作・培地調製は最新版Protocolを参照してください。

## 4.2 実施時刻は厳密でなくてよい

培養操作の時刻は、日単位のサイクルが守られていれば、朝5時〜正午前など一定幅は許容されています。

ただし、担当者が「誰かやるだろう」で消えるのが一番危険です。

**担当者名と実施日だけは明示**します。

## 4.3 培養異常は「混ぜない・強行しない」

260728では培養異常のため精製を中止し、260817では14 L中2 L分を除外して12 Lで実施しました。

最新版Protocolでは以下を現行の重要事項としています。

- 各段階で外観・増殖状態を確認
- 液体培養は複数視野で、細菌サイズの微小粒子まで検鏡
- contamination疑いの培養は混ぜない
- quality / quantity を確保できないと判断した時点で使用・精製を中止

責任者は、「予定通り実施すること」より「悪い培養を混ぜないこと」を優先します。

# 5. 1週間前：Protocol改訂 + リマインド

## 5.1 リマインドの目的

1週間前メールは単なる挨拶ではありません。

主な目的は次の4つです。

1. 最新Protocolを全員へ共有する
2. 昆さんを含む各担当者に当日の予定を再認識してもらう
3. 今後の精製予定も同時に見せ、次回日程の認識ズレを防ぐ
4. 中止するなら**液体培養へ入る前に止める**機会を作る

実際の送信日は概ねD-7前後で構いません。曜日と液体培養日を見て、**D-4より前に届くこと**を優先します。

必要ならN-in-1版PDFも添付します。

# 6. Protocolの毎回改訂

毎回ゼロから作り直す必要はありません。前回Protocolを複製し、必要箇所だけ更新します。

## 6.1 最優先：注意事項ページ

注意事項は、**直近で本当に注意すべき事項だけを上段に残す**方針です。

現在の代表例：

- 脱膜後、とくにUnoQ溶出後〜最終回収は低温・迅速・低侵襲
- tip pre-wet
- 底面接触、強いpipetting、2段押し、気泡、不要な振動を避ける
- 培養各段階の異常確認
- contamination疑いは混合せず、必要なら中止

古くなった反省は削除せず、**要約して「過去の反省・改善記録」へ下げる**ようにします。

このページの主な読者は「今日の自分」より、数年後の後輩です。

### 記載ルール

- 直近：具体的な注意を1〜2行で
- 過去：原因と改善を圧縮して1項目に
- 感情や経緯説明を長く書かない
- 同じ内容が重複したら統合

## 6.2 タイムスケジュール

最新版Protocolでは、担当を以下の記号で整理しています。

- `◎`：主担当
- `○`：サブ担当
- `△`：フォロー

並行作業は色分けして、「同時刻に誰がどこへ行くか」が一目で分かるようにします。

人員構成が変わる回こそ、ここを丁寧に直します。

## 6.3 Protocol本文

最近は大幅改訂は少ないですが、以下は必ず確認します。

- 今回回収するIDA種
- d / e 等の変更
- sample数に依存する本数
- 回収Fr
- 担当者
- 最新の注意事項

見落としやすい可変箇所は、既存のハイライトを維持してください。

## 6.4 UnoQ前回データ

UnoQページには、前回の以下の値を載せています。

- Fr位置
- UV280
- Cond
- 目安時刻

最新版Protocolでは前回データとして260817が反映されています。

更新すると当日便利ですが、**Resultsや実験Noteを見れば復元可能なので絶対条件ではありません**。

更新する場合は、前回クロマト画像も同時に差し替えます。

## 6.5 濃縮の前回記録

ResultsとProtocolで前回濃縮回数・volumeを参照する場合、最新回へ更新します。

これも必須ではありませんが、当日の終了volume感を掴む助けになります。

# 8. 前日準備

前日準備は「やらないと精製不可能」なものと「朝を楽にする」ものが混在しています。

最新版Protocolの前日準備を正本にしつつ、責任者として以下を確認します。

## 8.1 物品・Falcon

Protocolでは、再利用Falconと新品Falconを工程ごとに事前準備します。

少なくとも、以下が当日朝に探し物にならない状態へします。

- 繊毛単離用50 mL Falcon群
- Dibucaine用
- HMDS用
- sucrose cushion用
- HMDE-superloop / 平衡化 / 脱塩 / 濃縮用
- sample希釈・超遠心後回収・UnoQ Fr・脱塩後回収用15 mL Falcon

具体的な本数は最新版Protocolに従います。

## 8.2 Dibucaine

25 mM Dibucaineを事前調製し、4 ℃保存 → 当日RTへ戻す運用です。

## 8.3 低温室

前日から冷やすものをまとめて準備します。

代表例：

- フラコレ用1.5 mL蓋なしチューブ
- syringe類
- 超遠心tube / balance
- filtrated HMDE
- HMDE + KCl
- filtrated MQ
- 必要なrotor

## 8.4 TEM側

- 液体窒素残量
- 光軸合わせ
- 酢酸ウラン
- grid残数
- 鍵・アクセス

を確認します。

## 8.5 朝を楽にする小準備

余裕があれば以下も前日に済ませます。

- MQを汲む
- HMDS用beakerを出す
- transport用カゴへ入れられるものを入れる
- 当日使う場所ごとに物品をまとめる

これらは最悪当日でも耐えますが、**朝の1時間を実験判断に使える状態にする**意味があります。

# 9. 当日の指揮

## 9.1 朝

最新版の目安では、

- 7:30 当日準備
- 8:30 鞭毛単離開始

です。

一人で朝準備を行うと約1時間、補助があると40〜50分程度が目安です。

責任者は遅刻リスクを見込み、**開始時刻より前に「誰が何を準備するか」まで決めておく**のが安全です。

## 9.2 当日の役割分担原則

責任者が見るべきポイントは次の5つです。

1. **人を余らせない**：同時進行できる工程を分ける
2. **一人に作業を集中させない**：特定の人が全部やろうとしたら分担する
3. **物品配置を共同作業向けにする**：作業者同士が交差しないように置く
4. **次工程の準備を前倒しする**：待ち時間を使う
5. **sampleを待たせない**：UnoQ後〜脱塩・濃縮は特に優先

責任者自身が作業へ入り込みすぎると、全体の遅延や抜けに気づけなくなります。

## 9.3 記録

最低限、以下を残します。

- 各主要工程の時刻
- 異常時刻
- Fr位置
- representativeな写真
- buffer / containerの異常
- sample量・濃縮volume
- TEM所見

あとから「何が起きたか」を復元できることが目的です。

## 9.4 大幅遅延時

大きく遅れた場合は、関係者へ早めに共有します。

- 昆さん：全体進行・受渡時刻
- UnoQ / 濃縮側の担当
- TEM担当
- 必要に応じて教員陣

「予定時刻を過ぎてから報告」ではなく、**遅れると分かった時点で見込み時刻を出す**方が後工程を組み替えやすくなります。

# 10. 当日中に回収するUnoQデータ

## 10.1 PCを確保する

Frが最後まで出たら、AKTA担当へ終了してよい旨を伝え、停止後にPCを使用できる状態へします。

別日にデータを取りに行くより、**当日中にUSB等へ移しておく**のが安全です。

## 10.2 UNICORNの基本

詳細は `UNICORN データ抽出マニュアル[260425]` を参照します。

実務上必要なのは次の4点です。

### A. Resultを開く

- `Evaluation`
- `Open`
- 対象日のResult fileを選択

Result名は `TK_YYMMDD_ChlamyDynein...` 系が多いです。

`Modified` は過去ファイルを開くだけでも更新される場合があるため、**更新日時だけで探さない**こと。

### B. 表示Curve

最新版Protocolでは概ね以下を表示します。

- `01 ... UV1_280nm`
- `03 ... UV1_320nm`
- `04 ... Cond`
- `11 ... Fractions`

過去のUNICORN manualはUV280 / Cond / Fractionsを基本としているため、**現行Protocolの320 nm追加を優先**してください。

### C. 値を読む

グラフ右クリック → `Marker` で位置の値を表示できます。

Resultsへ最低限入れるもの：

- Base
- peak UV280
- `UV280 - Base`
- Cond
- Fr番号
- 回収Fr

### D. Export

`File > Export > Curves`

欲しいCurveを `Curves to export` へ送り、Excel形式で保存します。

Peak tableが必要なら、

- 右クリック → `Peak Integrate`
- UV280を選択
- Baselineを確認
- `File > Export > Peak Table`

で出力できます。

## 10.3 Results用スクリーンショット

UnoQ Fr結果スライドでは、**a/b前の谷〜fの最大peakまでが入る最小幅**にzoomすると比較しやすくなります。

Fr labelとpeakが読める状態でスクリーンショットを取得します。

## 10.4 Chromato比較

過去runと重ねる場合はCompare系機能を使います。

基本イメージ：

1. 比較対象Resultを選ぶ
2. Compare / Multiple Peak Compare系からCurveを検索
3. UVとFraction関連Curveを選択
4. 重ねた状態で表示範囲を揃える
5. Resultsへ貼る

UNICORN versionやUIで表記が異なるため、操作名が一致しない場合は無理に進めず、元ResultとExportを保存してから確認します。

# 11. Bradford濃度測定データを作る

共有OneDrive内の以下を使用します。

```text
04.大量精製\Results\Bradford濃度測定_大量精製.xlsx
```

## 11.1 毎回の使い方

1. 前回sheetを複製
2. sheet名を `YYMMDD` に変更
3. 日付を更新
4. BSA standardのOD595を入力
5. sample OD595を入力
6. `Dilution` を実際の希釈率へ変更
7. `True (ug/ml)` を確認
8. graphを確認
9. Results PPTX用にスクリーンショット

260817 sheetでは、a/b・c・d・gを2倍希釈として入力し、最終値が自動計算される構造になっています。

## 11.2 原則レンジ

現在の運用では、通常は**BSA 0–250 µg/mL系列**を使います。

過去の反省会では、多少レンジを超えても「sampleを待たせないスピード」を優先し、0–500系列の再測定を毎回行う必要はないという整理になっています。

明らかに外れた場合は希釈率を調整して測る方が運用しやすいです。

> 測定精度を上げるためにsampleを長時間待たせることは避けます。

# 12. Results PPTXを作る

Resultsは「当日報告資料」ではなく、**次回の比較基準・sample在庫台帳・反省会記録を兼ねる履歴ファイル**です。

## 12.1 最初にやること

前回のResults PPTXを**ファイルごと複製**します。

そのまま上書きし始めず、まず前回分のうち後から参照するセクションをPPTX末尾へ退避コピーします。

少なくとも以下：

- Chromato比較
- ネガステ
- 精製の反省と改善
- 反省会

その後、今回セクション側を更新します。

## 12.2 日付の更新

各スライド右上等の `260817` のような日付を今回日付へ変更します。

PowerPointの置換を使って構いませんが、**過去結果・過去反省の年月日まで誤置換しない**こと。

「PPTXを後からめくったとき、どのrunのスライドか即分かる」ことが目的です。

## 12.3 セクションごとの更新内容

### A. 精製の反省と改善

精製直後は、

- 最終濃度
- 回収Fr数
- beads数
- TEM / neg-stain概要
- 発生した問題

を簡潔にまとめます。

反省会後に、原因候補・次回actionを追記します。

### B. ネガステ結果一覧

反省会では最初にneg-stainを見ることが多いため、4種を一覧で比較できるslideを維持します。

### C. 反省会

精製直後は空欄で構いません。

反省会後に、

- 結論
- 観察事実
- 原因候補
- 次回action
- USE / HOLD / Cryo-EM不使用等の判断

を残します。

260817では、最終的に4試料すべてHOLD、Cryo-EM不使用とし、UnoQ直後から最終までのどこで短化したかを次回切り分ける整理になっています。

### D. 基準結果

原則変更しません。

過去の良好runをgolden standardとして、

- UV280
- Base
- Fr
- 濃度
- neg-stain

を比較するための基準です。

### E. UnoQ Frの結果

前回表を「前回」側へコピーし、今回表をclearして入力します。

入力項目：

- Base
- UV280
- 差引値
- Cond
- Fr位置
- 回収Fr
- 回収数
- 最終濃度

Frの見え方はrunごとにずれるため、a/b/c/d/e/g/fのlabel位置も調整します。

下部の赤字等には、前回比較の所感を1〜2行で書きます。

例：

- 最近2回より高い
- 12 Lを考慮すると強い
- 2023基準には未達
- peak位置が約1 Fr shift

### F. Chromato比較

Compare Curve等で過去runを重ねた画像を貼ります。

比較条件が揃っていない場合は、その旨を書きます。

### G. 濃縮

各sampleについて、濃縮回ごとのvolumeを記録します。

前回と今回を並べ、

- 濃縮回数
- 終了volume
- 異常な回収loss
- 泡・操作上の問題

が比較できるようにします。

### H. 濃度測定

Bradford Excelのgraph / tableを貼ります。

### I. ネガステ個別slide

画像と所感を更新します。

前回PPTXを複製した直後に、**今回入力欄側の画像と赤文字をclear**しておくと、前回画像の残存ミスを防げます。

画像・赤文字の位置は既存placeholderに合わせます。

### J. サンプル残数

今回凍結したbeads数を追記し、使用済みsampleの残数も更新します。

ここは地味ですが、Cryo-EM sample選定に直結するため重要です。

最低限：

- 精製日
- 濃度
- 残数
- 最終使用日
- 備考
- HOLD / 使用不可等

### K. IDA過去精製履歴

各IDA種の履歴表へ今回rowを追加します。

代表項目：

- 精製日
- 担当
- 培養scale
- UV280
- Base
- Base差引
- Cond
- 回収Fr
- Fr数
- 濃縮回数
- Final Vol
- 濃度
- beads
- neg-stain / 備考

表が厚くなった場合は、cell marginを小さくして視認性を確保します。

### L. 使用buffer記録

作成batchと使用日を更新します。

2026-08のResultsでは4種精製時準備量の目安として、

- MQ 1 L
- HMDE 750 mL
- HMDE + 1 M KCl 300 mL

が記録されています。

batch IDと残量も追跡します。

# 18. 現時点で特に重要なトラブル知識

## 18.1 UnoQ後〜最終sampleのquality低下

260817では、a/b・c・dで**UnoQ Fr直後の方が最終sampleより良好**という所見があり、UnoQ後の脱塩〜濃縮〜回収工程での品質低下が疑われました。

そのため次回以降は、Fr直後と最終sampleを直接比較できるようにします。

現行注意：

- tip pre-wet
- 底面にtipを当てない
- 強いpipettingをしない
- 2段押ししない
- 気泡を入れない
- 不要な振動を避ける
- sampleを待たせない

## 18.2 Bufferの取り違え

260817では、MQとHMDEのlabelが分かりにくく取り違えが発生しました。Recoveryできたため全体への影響は回避されました。

改善：

- labelを短く大きく明確にする
- 物理的な置き場所を分ける
- MQ：フラコレ側
- HMDE / HMDE+KCl：実験机側

「色や瓶形状で覚える」ではなく、**labelと置き場所の二重化**で防ぎます。

## 18.3 培養contamination

260728は中止、260817は1本除外という事例があります。

異常を見つけたときは：

1. 他の培養と混ぜない
2. 顕微鏡で複数視野確認
3. pellet / 色 / 動きを記録
4. 教員と相談
5. quality / quantityが成立しなければ中止

「せっかくここまで培養したから」は判断基準にしません。

## 18.4 Fr collector / UNICORN異常

Fr飛びや通信エラーが起きた場合は、そのまま続行せずProgramを止め、正しいFrへ戻して再開します。

同時に、

- 発生時刻
- 実際に入ったtube
- chromatogram上の位置

を記録します。

## 18.5 濃度が高いとき

UnoQ peakが高く高濃度が予想されるsampleは、凝集防止のため**限界まで濃縮せず一歩手前で止める**判断があります。

「高濃度ほど常に良い」ではありません。

# 21. 引継ぎ完了の判定

「説明を聞いた」だけでは引継ぎ完了としません。

前嶋・増田それぞれが、最終的に次を自力で実行できれば完了です。

- 日程候補を作れる
- 培養日まで逆算できる
- 遠心機・TEM・部屋を予約できる
- 最新Protocolを更新できる
- 当日の役割表を作れる
- 異常時に中止 / 継続判断を相談できる
- UNICORNから必要dataを取り出せる
- Bradford Excelを更新できる
- Results PPTXを前回から正しく更新できる
- sample残数・履歴を更新できる
- 速報 → 反省会 → 最終共有まで回せる
- NASへ第三者が探せる形で保存できる

理想は、

1. 1回：横で見ながら担当
2. 1回：本人lead、前任者がbackup
3. 1回：本人だけでlead

の順で確認することです。

# 22. このマニュアルの更新ルール

この文書は、個々の細かい実験条件を蓄積する場所ではありません。

更新対象は、

- 運用フローが変わった
- 予約方法が変わった
- 担当体制が変わった
- Results / 保存方法が変わった
- 毎回同じ運用ミスが出る

といった**再現性のある運用知識**です。

重複してきたら、この運用マニュアルへ抽象化して移します。
